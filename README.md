# AI City

각자의 페르소나와 기억을 가진 AI 주민들이 사는 관찰형 도시 게임입니다. Google 로그인한 방문자는 관찰자로 도시 지도/활동/관계/프로젝트를 보며, 도시 지도 또는 검색 가능한 주민 목록에서 한 명을 선택해 따라봅니다. 공유 세계는 Git 기반 공개 JSON, 인증은 Firebase Authentication입니다. 운영은 WORLD_GUIDE.md를 참고하세요.

## GitHub 배포

1. Settings → Environments → **ai_city**에 아래 6개 항목을 Variables 또는 Secrets로 등록합니다. 같은 이름이 양쪽에 있으면 Secrets가 우선합니다.
2. Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 지정합니다.
3. main 푸시 또는 Actions → Deploy AI City → Run workflow로 배포합니다.

```
VITE_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN
VITE_FIREBASE_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET
VITE_FIREBASE_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID
```

변수 누락 시 빌드를 중단하며, 누락한 변수 이름만 로그에 표시합니다. 값은 로그에 출력하지 않습니다. Firebase 웹 설정은 빌드된 JavaScript에서 공개됩니다. 서비스 계정/private_key는 이 변수에 넣지 마세요. 데이터 접근은 Firebase 인증과 보안 규칙으로 제한해야 합니다.

빌드 job이 ai_city Environment를 사용합니다. 배포 job은 GitHub Pages의 github-pages Environment를 별도로 사용합니다. ai_city에 브랜치 제한/승인 규칙이 있다면 main을 허용해야 합니다.

배포 주소: https://sohn0356-git.github.io/ai_city/

## 로컬 개발

```sh
npm ci
cp .env.example .env.local
# .env.local에 Firebase 콘솔의 웹 앱 설정값 입력
npm run dev
```

```sh

```

로컬 주소도 /ai_city/ 경로를 사용합니다. 실제 환경변수 값은 커밋하지 마세요. package-lock.json을 포함하며 배포와 로컬 모두 npm ci로 동일한 의존성을 설치합니다.

## Firebase 사용

src/firebase.js는 실제 사용하는 app과 auth만 초기화합니다. 현재 세계는 공개 JSON을 읽으며 Firestore/Storage SDK를 초기 화면에서 로드하지 않습니다. 초기화 성공은 Firebase 서버 데이터 접근 성공을 의미하지 않습니다. Google 로그인을 사용하려면 Firebase Authentication → Settings → Authorized domains에 sohn0356-git.github.io를 등록하고, 사용할 로그인 제공자와 Firestore/Storage 규칙을 설정하세요. Google 로그인 구현은 포함되어 있지만 콘솔의 Google 제공자 활성화/승인 도메인 설정은 별도로 필요합니다. 이 프로젝트는 Firebase 보안 규칙이나 기존 데이터를 변경하지 않습니다.

## PWA

Android Chrome에서는 앱 설치, iPhone Safari에서는 공유 → 홈 화면에 추가를 사용합니다. 서비스 워커는 프로덕션 빌드에서만 등록되며 /ai_city/의 정적 앱 파일만 캐시합니다. Firebase 요청/사용자 데이터는 캐시하지 않습니다. 새 버전은 기존 앱 탭을 모두 닫은 후 다시 열면 적용됩니다. 앱 화면은 오프라인에서도 열 수 있지만 온라인 게임 데이터에는 연결이 필요합니다.

## 의존성 유지

Firestore의 Node.js 전용 전이 의존성 @grpc/grpc-js는 보안 패치를 위해 1.14 이상으로 override합니다. 브라우저에서는 해당 gRPC 코드를 사용하지 않습니다.

- VITE_ADSENSE_SLOT: 생성한 반응형 디스플레이 광고 단위의 숫자 ID

환경변수가 비어 있으면 기본 광고 단위를 사용하고, 설정된 ID의 형식이 잘못되면 광고를 요청하지 않습니다. 사용자가 제공한 AdSense 공통 스크립트는 index.html의 head에서 항상 한 번 로드합니다. 광고는 실제 방문자가 영역 근처로 스크롤했을 때 한 번 요청합니다. 2시간 회차나 세계 데이터 갱신은 광고를 새로 요청하지 않습니다. AI 주민/예약 작업은 광고 노출이나 클릭을 생성하지 않아야 합니다.

실제 광고 송출에는 AdSense 사이트 승인과 계정에서 요구하는 게시 설정이 필요합니다. 코드 추가가 승인/수익을 보장하지 않습니다. ads.txt가 요구되는 경우 `https://sohn0356-git.github.io/ads.txt`라는 도메인 루트에 본인 게시자 ID로 게시해야 합니다. 이 저장소의 `/ai_city/ads.txt`는 루트 파일을 대신하지 않습니다. 루트는 별도 `sohn0356-git.github.io` 저장소 또는 사용자 지정 도메인에서 관리할 수 있습니다. 대상 지역에 필요한 동의/개인정보 안내는 광고 활성화 전에 AdSense 안내에 따라 준비하세요.

## 화면과 코드 구조

- **도시**: 지도와 현재 주민 상태. 건물 선택은 그 장소의 현재 주민을, 주민 선택은 개인 상태를 보여줍니다. 동굴은 필요할 때 별도로 엽니다.
- **주민**: 이름·직업·활동 검색과 현재 장소·활동 종류 필터. 한 명을 고르면 도시 화면에서 따라봅니다.
- **기록**: 최근 소식 검색·페이지 이동, 프로젝트, 저장된 회차 비교. 실제 완료 기록과 예정 활동을 구분합니다.
- 개인 상세의 일정·기억·탐험·소지품은 열 때 로드합니다. 세계 JSON과 영구 보상 원장은 화면 탐색으로 변경하지 않습니다.

앱 조합은 src/App.jsx, 인증·연결·시계·PWA 상태는 src/hooks/, 공통 관찰 모델과 선택 전이는 src/observation.mjs, 각 화면은 src/ui/에 있습니다. main.jsx는 앱 시작만 담당합니다. 지도·명단·개인 상태·던전은 같은 시각과 활동 스냅샷을 사용합니다.

세계 연결은 중복 요청을 합치고 20초 지연 시 재시도를 안내합니다. 연결 실패 시 마지막 스냅샷을 유지하고, 탭이 숨겨지면 주기적 시계·새로고침을 멈춥니다. 저장된 일정이 모두 끝나면 다음 갱신 대기 상태를 표시하며 새 활동을 만들어내지 않습니다.

검증: npm test, npm run build. 관찰 위치·필터·예약 전환·세계 불변성과 네트워크 요청 병합·실패 후 재시도는 scripts/observation.test.mjs 및 scripts/world-client.test.mjs에서 검증합니다. 로컬 화면 테스트 시 광고 요청을 차단하고 인증은 테스트에서만 모킹하며 프로덕션에 우회 코드를 추가하지 않습니다.

## 자동 액션 세계와 일상 재생

이제 기본 관찰 화면은 `public/life.json`의 자율 생활을 사용합니다. 기존 `world.json`·주민 후보·진행 중이던 과거 일정과 원장은 그대로 보존하며 새 엔진의 시작점으로 삼습니다. 자율 세계가 아직 없으면 이전 관찰 화면으로 연결됩니다.

- 주민은 에너지·허기·체력·직업·성격과 현재 장소에 따라 가중 랜덤으로 다음 액션을 선택합니다. 외부 LLM 호출 없이 재현 가능한 시뮬레이션입니다.
- 이동은 **출발지, 목적지, 초 단위 소요 시간, 좌표 경로**를 받습니다. 도착 전에는 목적지에서 다른 행동을 할 수 없습니다.
- 작업·식사·휴식·이웃 대화는 각 입력값과 실제 결과를 남깁니다. 같은 장소에 머무는 이웃끼리 대화하고, 식재료가 부족하면 수확을 도우며, 피곤하면 쉽니다.
- 탐험은 준비 → 동굴로 이동 → 탐색 → 확률적 조우/대련 → 탐색 지속 또는 귀환 → 회복으로 이어집니다. 제한 시간, 귀환 체력 기준, 최대 조우 횟수를 적용합니다. 기존 전투·최초 처치 XP·골드·정수 규칙을 재사용합니다.
- **일상 재생**에서 재생/일시정지, 1–120배속, 시간 슬라이더, 날짜 선택을 사용합니다. 액션 로그의 ‘여기서 재생’으로 특정 주민의 행동을 따라볼 수 있습니다. 재생은 저장된 결과를 적용하며 다시 정산하거나 랜덤을 새로 뽑지 않습니다.

### 자동 실행과 저장

`.github/workflows/autonomous.yml`은 5분 간격의 예약 실행 및 수동 실행을 지원합니다. 코드가 처음 반영될 때도 실행합니다. `npm run world:tick`으로 지난 실제 시간의 완료 액션을 순서대로 처리하고 life.json과 `public/life/history/YYYY-MM-DD.json.gz`, 날짜 색인을 커밋한 다음 배포 워크플로를 직접 호출합니다. GitHub 기본 토큰의 푸시가 다른 워크플로를 자동으로 실행하지 않는 경우도 이 연결로 처리합니다.

GitHub 예약 실행은 지연될 수 있습니다. 화면은 마지막 저장 상태에서 같은 시드와 규칙으로 최대 10분까지만 진행을 미리 표시하며, ‘실제 액션 로그’와 과거 재생은 서버에 저장된 기록만 사용합니다. 저장이 더 늦어지면 지연 상태를 표시합니다. 브라우저를 닫아도 예약 작업은 세계를 진행합니다.

`world:tick`은 **파일을 수정하는 실행 명령**입니다. 검사만 하려면 `node scripts/check-life.mjs`를 사용합니다. 긴 중단 후에는 한 번에 최대 6시간씩 순서대로 따라잡으며, 중간 시간의 기록을 건너뛰지 않습니다. 현재 빠른 재생 버퍼는 최근 약 1,200개 로그이고, 이전 기록은 날짜별 gzip 파일에 보존합니다. 서비스 워커는 이 파일들을 일괄 사전 캐시하지 않습니다.

### 액션 확장

- `src/simulation/catalog.mjs`: 액션 종류, 입력값, 기본 시간 범위, 선택 가중치, 탐험 기준.
- `src/simulation/engine.mjs`: 파라미터 검증, 실행, 완료 효과, 다음 액션 선택, 탐험 단계와 중복 없는 정산.
- `src/simulation/replay.mjs`: 경로 보간, 읽기 전용 실시간 미리보기, 과거 프레임 복원과 체크포인트.
- `scripts/tick-life.mjs`: 실제 시각까지 실행하고 일별 기록을 저장하는 작업자.

예를 들어 이동 요청의 형태는 다음과 같습니다. 출발지는 실제 시작 위치와 일치해야 하며, 경로를 생략하면 기본 도로 경로를 계산합니다.

```js
{ type: 'move', params: { from: 'hall', to: 'farm', durationSeconds: 120 } }
```

새 행동을 추가할 때는 입력 검증·수행 조건·완료 효과·기록·리플레이 표현을 함께 정의하세요. 진행 중 액션의 경로·능력치·몬스터·전투 턴 스냅샷은 바꾸지 않습니다. 기존 로그와 원장을 초기화해 새 규칙을 적용하지 않습니다.

검증은 `npm test`와 `npm run build`입니다. `scripts/life-engine.test.mjs`는 실행 간격에 무관한 결정성, 이동 시간, 하루 동안의 자원/체력 조건, 탐험 귀환, 중복 정산 방지, 재생 불변성, 버퍼 압축, 날짜별 기록 이어쓰기와 gzip 응답 처리를 확인합니다.


## 생활 경제·생존·인구

자율 주민은 이제 일을 마친 뒤 임금을 받고, 자기 지갑으로 음식을 구매해 먹습니다. 기본값은 완료한 생산 작업 2G, 음식 1개 2G, 치료 4G입니다. 음식은 공용 재고에서 개인 보관함으로 이동하며 구매와 식사는 별도 액션/기록입니다. 돈이나 재고가 부족하면 구매하지 못하고, 주민은 임금이나 식량을 마련하려고 일합니다. 구매한 음식은 세계 1일 뒤 소비 기한이 지납니다. 모든 수입·지출은 기존 거래 원장 형식으로 한 번씩 기록합니다.

기본 시간은 **현실 1시간 = 세계 1일, 세계 30일 = 나이 1년**입니다. 허기는 세계 시간에 따라 오르고 음식 섭취로 내려갑니다. **허기 100이 세계 2일 연속 지속되면 사망**합니다. 휴식만으로 허기가 없어지지는 않습니다. 질병은 체력을 감소시키며 치료를 받거나 기간이 지나면 회복할 수 있습니다. 질병으로 체력이 0이 돼도 사망합니다.

60세부터 상태 이상 확률이 높아지고 나이가 들수록 증가합니다. 85세부터 노쇠 사망 위험이 생기며 105세가 상한입니다. 새 주민은 매 세계일 25% 확률로 한 명씩 성인으로 입주합니다. **현재 활동 인구는 언제나 최대 100명**이며, 사망하면 활동 목록·지도·다음 행동에서 즉시 제거합니다. 인구가 0이어도 입주 추첨은 계속됩니다. 신규 ID는 사망한 주민의 ID를 재사용하지 않습니다.

사망한 주민의 과거 행동·거래·전투·정수 기록은 지우지 않습니다. 리플레이에서 그 당시 살아 있던 주민과 체력·허기·재산을 복원할 수 있도록 departed 이력과 입주/사망 이벤트를 보존합니다. 나이·상태 이상·지갑·보유 음식은 개인 카드에서, 인구와 누적 입주/사망 수는 도시 상단에서 확인합니다.

생존 규칙은 기존 자율 상태가 실제 시각까지 따라잡힌 뒤 활성화하며, 지난 공백 시간에 소급해 주민을 죽이거나 음식값을 청구하지 않습니다. 기존 주민은 활성화 시 18–55세를 배정받고 기존 경험치·돈·기억을 유지합니다. 이미 시작된 액션의 입력과 비용은 보존하고 새 액션부터 임금·유료 구매를 적용합니다. 기본 수치는 src/simulation/survival.mjs의 SURVIVAL_RULES에서 조정합니다.
